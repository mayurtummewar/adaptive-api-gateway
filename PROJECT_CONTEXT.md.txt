# AI-Powered API Security Gateway

## 1. Project Objective

Build an adaptive API security gateway that uses an AI-based anomaly detection engine to analyse incoming API traffic and influence gateway security decisions.

Expected decisions:
- ALLOW
- RATE LIMIT
- BLOCK

The project uses an e-commerce application to generate realistic API traffic for development, testing and model evaluation.

## 2. Architecture

Client (Angular)
    |
    v
Apache APISIX API Gateway
    |
    +----> FastAPI E-commerce Backend
    |             |
    |             v
    |         PostgreSQL
    |
    +----> AI Security Engine (FastAPI + PyTorch)

The AI engine is intended to analyse API traffic independently of the e-commerce business logic.

## 6. Important Development Decisions

- Keep the e-commerce backend as a modular FastAPI application initially.
- Use PostgreSQL for persistent application data.
- Use APISIX as the entry point for frontend API requests.
- Keep Angular development outside Docker initially.
- Run Angular locally using Node.js and npm.
- Containerize the frontend later for deployment.
- Prioritize realistic API traffic generation before finalizing AI model features.

## 7. Frontend Dependency Warning

The Angular project uses Angular 13.

Installation required:
npm install --legacy-peer-deps

Reason:
angular-responsive-carousel@2.1.2 declares a peer dependency on Angular 11.

Installation reported 127 vulnerabilities, including 9 critical.

Do not blindly execute npm audit fix --force.
Review and update dependencies carefully before deployment.
