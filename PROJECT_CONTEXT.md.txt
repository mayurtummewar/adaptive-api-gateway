# AI-Powered API Security Gateway

## 1. Project Objective

Build a demonstrable e-commerce application whose API traffic passes through
an adaptive security gateway. An AI anomaly-detection service will contribute
explainable gateway decisions while the e-commerce flow demonstrates realistic
products, cart, and order traffic.

The final demonstration should include both:

1. A working e-commerce flow.
2. AI-powered gateway security decisions.

The target policy is:

- `ALLOW`
- `RATE LIMIT`
- `BLOCK`

## 2. Current Repository Status

This section describes the repository as it currently exists. A feature must
not be marked complete here or elsewhere until it has been tested.

### Frontend

- React/Vite application is under `frontend/`.
- React Router provides shop, product detail, bag, local authentication, and
  order history pages.
- Product browsing, search, categories, authentication, cart changes, checkout,
  and order history use `/api/*` through APISIX.
- The complete signup-to-order flow has been verified through the live gateway.

### Backend

- `backend/` is one independently deployable FastAPI codebase with three
  Compose service roles: `identity-service`, `catalog-service`, and
  `commerce-service`.
- All roles use the existing PostgreSQL database; the identity role owns local
  signup/login JWTs, catalog owns products, and commerce owns user carts and
  orders.
- Startup creates compatible tables and adds the user ownership columns needed
  by existing local data.
- The complete PostgreSQL-backed signup, product, cart, stock decrement, order,
  and order-history flow has been verified through APISIX.

### Gateway and Infrastructure

- `compose.yaml` declares etcd, APISIX, PostgreSQL, three FastAPI service roles,
  and the AI engine.
- `apisix/config.yaml` configures APISIX to use etcd.
- `scripts/apply_apisix_routes.py` applies separate identity, catalog, cart,
  and order routes to the APISIX Admin API and removes the old catch-all route.
- Each public API route uses the AI pre-function and APISIX `limit-count`
  (`60` requests per minute per client address). The counter is gateway state,
  not an AI request-body feature.
- Vite proxies `/api` requests to the local APISIX gateway during development.
- The Compose stack is running locally, and the frontend-to-backend path,
  signup/login, cart, checkout, and order history have been smoke-tested
  through APISIX.

### AI Security Engine

- `ai-engine/app.py` defines a separate FastAPI scoring service.
- The service loads a supervised Random Forest classifier and policy
  thresholds from `classifier_metadata.json`.
- `/health` reports model readiness and `/score` accepts the eight trained
  request features.
- `/score` currently returns `ALLOW`, `RATE LIMIT`, or `BLOCK` using
  suspicious-probability thresholds of `0.5` and `0.9`.
- `train_classifier.py` trains the active model from the labeled traffic
  dataset. A 5-fold benchmark on the current 100-row dataset produced no
  false positives or false negatives.
- The earlier autoencoder remains available for comparison, but its
  95th-percentile reconstruction threshold produced false positives on normal
  traffic and is not the active model.
- The AI service now has a CPU-only Docker image and runs in Compose on local
  port `8001`; `/health` confirms that the model artifacts load.
- Representative scorer tests produce `ALLOW` for normal traffic, `RATE LIMIT`
  for burst traffic, and `BLOCK` for unusually large requests.
- The model and dataset still require broader evaluation; this is not yet a
  production-ready security policy.
- APISIX calls the AI scorer during request rewriting and enforces
  `RATE LIMIT` as HTTP 429 and `BLOCK` as HTTP 403. AI service failures fail
  closed with HTTP 503 rather than silently allowing traffic.

## 3. Intended Architecture

```text
React/Vite frontend
        |
        v
Apache APISIX API Gateway <----> etcd
        |          |          |
        v          v          v
 identity     catalog     commerce
 service      service      service
        \          |          /
              PostgreSQL
                    ^
                    |
              AI security engine
```

APISIX is intended to be the public API entry point. The backend owns
e-commerce business logic and persistence. The AI engine remains independent
and evaluates request traffic rather than product, cart, or order rules.
